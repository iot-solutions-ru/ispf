# Разбор эталонного примера: учёт простоев и рулонов печатной линии (`mes-ogp-events`)

> **Статус:** Lab — пример цехового приложения для рулонного производства: фиксация остановов и дефектов полотна, карта рулона, корректировка начальником смены и очередь выгрузки в 1С. Метки зрелости: [doc-status.md](doc-status.md).

Пакет **`mes-ogp-events`** ([`examples/mes-ogp-events/`](../../examples/mes-ogp-events/)) демонстрирует организацию рабочего места оператора печатной или бумагоделательной машины средствами стандартных виджетов и скриптовых функций ISPF.

---

## 1. Установка и вход в приложение

```powershell
node examples/mes-ogp-events/generate_bundle.mjs
.\examples\mes-ogp-events\deploy.ps1
```

- Адрес пульта оператора: `?mode=operator&app=mes-ogp-events`
- Узел логики приложения (`SINGLETON`): `root.platform.singleton-blueprints.mes-ogp-events-hub-v1`

---

## 2. Основные рабочие сценарии

### Сценарий 1. Регистрация приладки с немедленной вырезкой дефекта (код `120`)
1. На экране **«Симулятор OGP»** подайте сигнал останова линии (`stop` через функцию `ogp_simulateSignal`) — в таблице необработанных сигналов появится новая запись.
2. Перейдите на экран оператора **«Регистрация события»** (`ogp-operator-hmi`).
3. В форме регистрации укажите причину **`120` (Приладка)**, включите признак немедленного удаления, укажите метраж и комментарий → нажмите **«Зарегистрировать»**.
4. Запись перейдёт в **«Журнал процесса»**, а на карте рулона отметится вырезанный участок.

### Сценарий 2. Отметка дефекта полотна для последующего передела (код `141`)
1. Подайте сигнал кнопки дефекта (`defect button`).
2. Выберите код **`141` (Брызги краски)** без немедленной вырезки, укажите номер рулона `P1` и затронутые ручьи продольной резки.
3. На карте рулона появится предупреждающая зона для следующего участка резки.

### Сценарий 3. Автоматическая группировка кратковременных остановов
Если в течение 300 секунд (`downtime_group_timeout_sec`) происходит несколько повторных остановов подряд, система автоматически объединяет их в одну сводную запись простоя с подсчётом числа срабатываний (`member_count`).

### Сценарий 4. Проверка начальником смены, выпуск этикетки рулона и выгрузка в 1С
- На экране **«Начальник смены»** (`ogp-shift-supervisor`) доступны сводный отчёт по простоям и форма корректировки записей (`ogp_updateProcessEvent`).
- На экране **«Выпуск рулона»** (`ogp-roll-release`) функция `ogp_buildRollLabel` формирует итоговый паспорт рулона `P1`.
- Все подтверждённые события автоматически ставятся в таблицу исходящего обмена `integration_outbox` для пакетной передачи в 1С по расписанию `ogp-1c-export`.

