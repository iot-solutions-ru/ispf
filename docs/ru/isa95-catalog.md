# Построение иерархии предприятия по стандарту ISA-95 (ГОСТ Р МЭК 62264)

> **Статус:** Stable — рекомендации по отображению уровней управления и иерархии оборудования стандарта ANSI/ISA-95 (ГОСТ Р МЭК 62264) в дереве объектов ISPF. Метки зрелости: [doc-status.md](doc-status.md).

Этот документ показывает, как представить классическую пирамиду автоматизации **ISA-95 / ГОСТ Р МЭК 62264** и структуру производственных мощностей предприятия с помощью стандартных механизмов ISPF.

**Связанные разделы:** [Модель объектов](object-model.md) · [Производственные шаблоны проектирования](manufacturing-patterns.md) · [Соответствие ГОСТ Р МЭК 62264 (части 2, 3, 4)](gost-mek-62264-parts-2-3-4.md) · [Эталонное решение MES](reference-mes-platform.md).

## 1. Отображение уровней ISA-95 на механизмы ISPF

| Уровень ISA-95 | Назначение уровня | Как реализуется в ISPF | Примеры в дереве объектов |
|----------------|-------------------|------------------------|---------------------------|
| **Уровень 4** | Бизнес-планирование и логистика (ERP) | Сводные SQL-отчёты, витрины данных и таблицы обмена (`outbox` / `inbox`) с 1С и SAP | `root.platform.reports.*`, интеграционные функции на узлах `SINGLETON` |
| **Уровень 3** | Управление производственными операциями (MES / MOM) | Процессы BPMN, рабочая очередь смены (`Work Queue`), функции расчёта OEE, генеалогия партий и изолированные таблицы приложения | `root.platform.workflows.*`, узлы `INSTANCE` линий и участков, таблицы `app_mes_*` |
| **Уровень 2** | Диспетчерское управление (SCADA / HMI) | Экраны оператора, мнемосхемы P&ID, правила тревог (`ALERT`) и корреляторы событий (`CORRELATOR`) | `root.platform.dashboards.*`, `root.platform.mimics.*`, `root.platform.alert-rules.*` |
| **Уровень 1** | Сбор данных и управление (ПЛК, счётчики, датчики) | Узлы устройств (`DEVICE`), протокольные драйверы, переменные и правила первичной обработки сигналов | `root.platform.devices.*` (Modbus, OPC UA, S7, МЭК-104, MQTT) |
| **Уровень 0** | Физический технологический процесс | Отражается через показания переменных устройств и семантические метки Brick / Project Haystack | Теги переменных и единицы измерения |

## 2. Рекомендуемая структура дерева оборудования

ISPF не навязывает жёстких имён папок, но для промышленных проектов рекомендуется единообразная иерархия **Предприятие → Цех (Площадка) → Линия (Участок) → Рабочий центр (Агрегат) → Датчики/ПЛК**:

```text
root.platform.instances.<предприятие>
  └── areas.<цех>
        └── lines.<линия>
              └── units.<агрегат>          ← цифровой двойник агрегата (INSTANCE, логика и KPI)
                    └── devices.<датчик>   ← узел опроса контроллера или датчика (DEVICE)
```

| Понятие ISA-95 | Что использовать в ISPF | Рекомендация |
|----------------|-------------------------|--------------|
| **Предприятие / Завод (`Enterprise / Site`)** | Корневая папка проекта (или ветка тенанта `root.tenant.<id>.*`) | Единая точка входа для прав доступа площадки |
| **Цех / Производственная зона (`Area`)** | Папка `CUSTOM` или экземпляр `INSTANCE` цеха | Группировка линий и сводные показатели цеха |
| **Производственная линия (`Production Line`)** | Экземпляр шаблона `INSTANCE` (например, `line-v1`) | Хранит расчёт OEE смены, статус линии и функции диспетчеризации |
| **Рабочий центр / Установка (`Work Unit`)** | Экземпляр шаблона `INSTANCE` | Держит логику конкретного станка или реактора |
| **Полевой контроллер / Датчик** | Узел `DEVICE` с настроенным драйвером | Отвечает только за приём телеметрии и передачу команд (логику на `DEVICE` не размещают) |
| **Партия, заказ, маршрутная карта (`Lot / Work Order`)** | Таблицы в SQL-схеме приложения + при необходимости узлы в `root.platform.mes.*` | Обрабатываются функциями приложения через шлюз BFF |

## 3. Основные задачи уровня MES (Уровень 3) и их реализация

| Задача управления производством | Штатный механизм ISPF |
|---------------------------------|-----------------------|
| Сменно-суточное задание и диспетчеризация | Таблицы заказов в схеме приложения + маршрут BPMN с выдачей задач в очередь оператора (`Work Queue`) |
| Расчёт эффективности оборудования (OEE) | Исторические правила расчёта (`kind: historian`, функция `oee(...)`) и функции BFF на узле линии |
| Контроль качества и учёт брака (SPC / QMS) | Таблицы проб и несоответствий, контрольные графики на дашбордах, процессы согласования брака в BPMN |
| Оповещение и эскалация при авариях и простоях | Правила тревог (`ALERT`) → корреляторы (`CORRELATOR`) → процессы эскалации с таймерами в BPMN |
| Отчётность для руководства и обмен с ERP | Узлы отчётов `REPORT` (выгрузка в XLSX / PDF / CSV) и транзакционная очередь `outbox` |
