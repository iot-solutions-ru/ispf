# Регламент испытаний кластера на отказоустойчивость и работу под нагрузкой

> **Статус:** Lab — методика проверки перехвата драйверов, синхронизации конфигурации и работы под нагрузкой при принудительной остановке узлов кластера. Метки зрелости: [doc-status.md](doc-status.md).

Этот документ описывает воспроизводимые испытания многоузлового кластера ISPF ([ADR-0028](decisions/0028-horizontal-active-active-cluster.md), [ADR-0029](decisions/0029-cluster-live-variable-replica-sync.md), [ADR-0030](decisions/0030-cluster-config-structure-replica-sync.md)): что проверяется автоматическими тестами на каждом коммите и как запустить длительный нагрузочный прогон с имитацией сбоев узлов в лаборатории.

**Связанные разделы:** [Кластер высокой доступности (`cluster.md`)](cluster.md) · [Развёртывание и конфигурация (`deployment.md`)](deployment.md) · [Тестирование платформы (`testing.md`)](testing.md).

---

## 1. Что проверяется автоматически и что проверяется на стенде

| Проверяемое свойство кластера | Автоматическая проверка в CI | Стендовый прогон под нагрузкой |
|-------------------------------|------------------------------|--------------------------------|
| Распределение и перехват блокировок драйверов (`platform_driver_locks`) | `ClusterFailoverIntegrationTest` | Повторная проверка под потоком телеметрии |
| Балансировка REST API и сохранение ответа `200 OK` при остановке одной реплики | `deploy/cluster-smoke-test.sh` (конфигурация `nginx-cluster.conf`) | То же |
| Время перехвата опроса устройства другой репликой после сбоя владельца | `deploy/cluster-smoke-test.sh` (норматив по умолчанию ≤ 45 с) | Проверка под входящим потоком |
| Синхронизация изменений структуры дерева между репликами (ADR-0030) | `cluster-smoke-test.sh --config-sync` | То же |
| Синхронизация текущих значений переменных в памяти реплик через NATS (ADR-0029) | `cluster-smoke-test.sh --live-var-lag` | Проверка при интенсивном потоке MQTT |
| Рост пропускной способности при добавлении реплик (`≥ 1,8×`) | `deploy/cluster-scale-load-test.py` | Замер на выделенном сервере |

---

## 2. Команды запуска испытаний кластера

Быстрая комплексная проверка кластера и коэффициента масштабирования:

```bash
export ISPF_CLUSTER_REQUIRE_DRIVER_LOCKS=1
bash deploy/cluster-smoke-test.sh --config-sync --live-var-lag
python deploy/cluster-scale-load-test.py --scale-factor-floor 1.8
```

Длительный лабораторный прогон с принудительной остановкой и возвратом реплики в середине теста (формирует отчёт в `deploy/journals/`):

```bash
bash deploy/cluster-soak-lab.sh                  # стандартный 30-минутный прогон
bash deploy/cluster-soak-lab.sh --duration-min 2 # короткий 2-минутный прогон
```

Подробный протокол испытаний и целевые нормативы времени восстановления приведены в полной английской версии: **[en/cluster-chaos-soak-runbook.md](../en/cluster-chaos-soak-runbook.md)**.
