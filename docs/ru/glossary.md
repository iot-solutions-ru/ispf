# Глоссарий терминов ISPF

> **Статус:** Stable — словарь терминов платформы простыми словами. Метки зрелости: [doc-status.md](doc-status.md).

Здесь собраны и переведены на обычный инженерный язык термины, которые встречаются в интерфейсе ISPF, API и документации. Если вы только знакомитесь с платформой, начните со страницы **[Как устроен ISPF](learn.md)** — там все эти понятия показаны на одном сквозном примере.

---

## А — Русские и общие понятия (быстрый перевод с английского)

| Как называется в интерфейсе / API | Что это по-русски | Краткий смысл |
|-----------------------------------|-------------------|---------------|
| **Object tree** | Дерево объектов | Единая иерархия всех узлов сервера (`root.platform.*`) |
| **Blueprint** (`SINGLETON` / `INSTANCE` / `MIXIN`) | Шаблон (модель) объекта | Типовая заготовка переменных, событий, функций и формул |
| **Binding rule** (`@bindingRules`) | Правило расчёта (привязка) | Формула автоматического пересчёта переменной по изменению входа или таймеру |
| **Alert rule** (`ALERT`) | Правило тревоги (уставка) | Проверка условия (например, перегрева) с записью события и оповещением |
| **Correlator** (`CORRELATOR`) | Коррелятор событий | Правило, которое ловит цепочку или пачку событий за окно времени и запускает реакцию |
| **Workflow** (`WORKFLOW`) | Процесс BPMN | Пошаговый сценарий обработки (автоматические действия + задачи оператору) |
| **Work Queue** | Рабочая очередь смены | Список активных задач оператора из процессов BPMN |
| **Mimic** (`MIMIC`, `scada-mimic`) | Мнемосхема SCADA | Графическая технологическая или однолинейная схема с живыми сигналами и кнопками управления |
| **Historian** | Архив истории (историк) | Подсистема записи, хранения и агрегации временных рядов |
| **Bundle** (`bundle.json`) | Пакет решения | JSON-манифест со всей конфигурацией приложения для хранения в Git и переноса между серверами |
| **UI pack** (`ui-pack`) | Пакет веб-интерфейса | Zip-архив собранного внешнего React-приложения оператора, раздаваемый с `/apps/<appId>/` |
| **BFF** (`/api/v1/bff/invoke`) | Шлюз вызова функций из UI | Единый HTTP-метод, через который экраны вызывают прикладные функции на объектах |

## Подробные определения (A–Z)

### Alert rule (Правило тревоги)

Узел типа `ALERT` в ветке `root.platform.alert-rules`. Проверяет условие на языке CEL при обновлении переменной объекта (например, `self.temperature.value > 80.0`). Поддерживает задержку срабатывания (`delaySeconds`), защёлку/гистерезис сброса (`deactivateExpr`), отправку уведомлений (вебхук, почта) и публикацию события в журнал. Подробнее: [Автоматизация](automation.md).

### Application (Прикладное решение / приложение)

Оформленный проект на базе ISPF со своей изолированной схемой таблиц в СУБД (`app_<id>`), SQL-миграциями, скриптовыми функциями, узлами дерева, экранами и маршрутами BPMN. Регистрируется в `root.platform.applications`. Важно: во время работы все сигналы, формулы, тревоги и экраны приложения выполняются в общем дереве объектов платформы, а не в отдельном стороннем процессе. Подробнее: [Руководство разработчика решений](solution-developer-guide.md).

### Binding rule (Правило расчёта / привязка)

Декларативное правило пересчёта на объекте (хранится в системной переменной `@bindingRules`). Схема работы: **когда сработать** (изменилась переменная, пришло событие, сработал таймер `periodicMs`) → **условие** (`condition` на CEL) → **формула** (`expression`) → **куда записать результат** (`target`). Может писать как в переменную своего объекта, так и в переменную другого узла дерева. Подробнее: [Правила расчёта (привязки)](bindings.md).

### Blueprint (Шаблон / модель объекта)

Описание типовой структуры узла (`BlueprintDefinition`): какие у него есть переменные, события, функции и правила расчёта. В ISPF три вида шаблонов:
- **`SINGLETON`** (одиночный узел логики) — создаёт единственный центральный объект-оркестратор для всего решения (например, диспетчерский узел станции или терминала).
- **`INSTANCE`** (шаблон типа экземпляров) — описывает тип оборудования или цифрового двойника (например, «Котельная», «Линия розлива», «Магазин»), по которому создаётся сколько угодно однотипных объектов со своей логикой.
- **`MIXIN`** (примесь) — дополнительный набор переменных и правил, который подключается к уже существующим объектам (вручную или автоматически по условию CEL).
Подробнее: [Шаблоны объектов (Blueprints)](blueprints.md).

### BFF (Backend-for-Frontend, `POST /api/v1/bff/invoke`)

Единая точка вызова серверных функций из пользовательского интерфейса (как встроенных форм, так и внешних React-приложений). Принимает путь к узлу логики (`objectPath`), имя функции (`functionName`) и входные параметры, проверяет права текущего пользователя и возвращает результат в стандартном формате.

### Bundle (`bundle.json`, пакет решения)

JSON-файл, в который собирается вся конфигурация прикладного решения: шаблоны и объекты дерева, SQL-миграции схемы приложения, функции, дашборды, процессы BPMN, отчёты и настройки меню оператора. Пакет хранят в Git, проверяют валидатором (`ispf validate`) и загружают на сервер через `POST /api/v1/applications/{id}/deploy`.

### CEL (Common Expression Language)

Лаконичный и безопасный язык выражений (разработка Google), на котором в ISPF пишутся арифметические формулы, пороговые условия тревог и ветвления в процессах BPMN. Пример: `self.pressure.value >= 4.5 && !self.maintenanceMode.value`. Полный справочник: [Язык выражений](expression-language.md).

### Change set (Набор изменений)

Подготовленный пакет правок дерева объектов, который можно сначала просмотреть (`preview` — что именно изменится) и согласовать перед применением (`apply`). Подробнее: [Совместная работа](collaboration.md).

### Claim (Взять задачу в работу)

Действие оператора в рабочей очереди (**Work Queue**): закрепление поступившей задачи процесса BPMN за собой на время её выполнения.

### Correlator (Коррелятор событий)

Узел типа `CORRELATOR` в `root.platform.correlators`. Отслеживает комбинации событий во времени (например, повторение аварии N раз за 10 минут или цепочку «событие А, затем событие Б») и запускает процесс BPMN либо формирует сводное событие. Подробнее: [Автоматизация](automation.md).

### Dashboard (Дашборд / экран оператора)

Узел типа `DASHBOARD` в `root.platform.dashboards`. Хранит раскладку виджетов на сетке **84×8** (числовые индикаторы, тренды, таблицы объектов, стрелочные приборы, мнемосхемы SCADA, кнопки вызова функций). Редактируется в конструкторе администратора, а оператору открывается в режиме только для чтения и управления. Подробнее: [Дашборды](dashboards.md).

### DataRecord и DataSchema

Формат хранения значений всех переменных в ISPF. `DataSchema` задаёт список полей и их типы (`DOUBLE`, `INTEGER`, `LONG`, `BOOLEAN`, `STRING`, `DATETIME` и др.), а `DataRecord` хранит строки данных. Для обычного датчика это одна строка, например `{ "value": 23.5, "unit": "°C" }`; для табличной переменной — несколько строк. Подробнее: [Модель объектов](object-model.md).

### Device (`DEVICE`, устройство)

Узел дерева объектов, представляющий реальный или эмулируемый контроллер, ПЛК, прибор учёта, канал MQTT или сетевой узел. На узле `DEVICE` работает протокольный драйвер и лежат переменные телеметрии/управления этого прибора. Прикладную логику станции или приложения на `DEVICE` не размещают — для неё используют узлы `SINGLETON` и `INSTANCE`.

### Driver и Driver pack (Драйвер и пакет драйвера)

Подключаемый модуль протокола связи (`modbus-tcp`, `opcua`, `s7`, `mqtt`, `snmp`, `iec104`, `dnp3`, `jdbc`, `virtual` и др.) в каталоге `data/drivers` (`ISPF_DRIVER_PACKS_DIR`). Опрашивает оборудование с заданным периодом или принимает входящие пакеты и обновляет переменные узла `DEVICE`. Подробнее: [Драйверы устройств](drivers.md).

### Explorer и Inspector (Дерево и инспектор свойств)

Две основные панели консоли администратора: слева в **Explorer** отображается иерархия дерева объектов, а справа в **Inspector** настраиваются свойства выбранного узла, его переменные, функции, события и правила расчёта.

### Federation (Федерация серверов)

Связка нескольких удалённых серверов ISPF (например, на цеховых или полевых площадках за NAT) с центральным диспетчерским сервером ISPF, включая буферизацию данных при обрывах связи (*store-and-forward*). Подробнее: [Федерация](federation.md).

### Historian (Архив истории / историк)

Подсистема записи и чтения истории изменений переменных (включается флагом `historyEnabled = true` на нужных тегах). Поддерживает однобазовый режим на PostgreSQL/TimescaleDB (оперативный слой), подключение ClickHouse для больших потоков и глубокой аналитики, а также выгрузку старых данных в файлы Parquet (долгосрочный архив). Подробнее: [История переменных](variable-history.md) и [Уровни хранения истории](historian-tiers.md).

### Hosted UI pack (`ui-pack`, встроенный пакет веб-интерфейса)

Zip-архив со скомпилированной статикой отдельного веб-приложения (обычно React + Vite) и файлом паспорта `ui-pack.json`. Устанавливается на сервер ISPF и открывается по адресу `/apps/<appId>/`, когда оператору нужен специализированный интерфейс со сложной графикой, картами или отраслевыми формами. Подробнее: [Разработка своего React-интерфейса](external-ide.md).

### MCP (Model Context Protocol)

Стандартный интерфейс (`POST /api/v1/ai/mcp`), через который внешние среды разработки (Cursor, VS Code) подключаются к серверу ISPF, читают структуру дерева объектов, проверяют пакеты `bundle.json` и вызывают инструменты платформы с учётом прав пользователя. Подробнее: [ИИ-студия и MCP](ai-development.md).

### Mimic (Мнемосхема SCADA)

Интерактивная векторная технологическая или электрическая схема (`root.platform.mimics.*`), собранная в браузерном редакторе из библиотеки символов P&ID / энергетики. Элементы схемы меняют цвет, уровень и показания по живым переменным дерева и позволяют подавать команды на оборудование. Подробнее: [Мнемосхемы SCADA](scada.md).

### Object tree (Дерево объектов)

Единая иерархия всех сущностей сервера ISPF с адресацией через точку от корня `root.platform` (например, `root.platform.devices.pump-01`). Узлами этого же дерева являются дашборды, мнемосхемы, правила тревог, корреляторы, процессы BPMN, отчёты и пользователи.

### Operator HMI (Режим оператора)

Полноэкранный режим работы веб-консоли (`?mode=operator` или автоматический вход под учётной записью с ролью `operator`). Показывает только назначенные рабочие экраны, журнал событий и очередь задач смены — без доступа к настройкам платформы. Подробнее: [Руководство оператора](operator-guide.md).

### PlatformRef (Ссылочный адрес элемента)

Единая запись адреса переменной, поля, функции или события через косую черту (`/`), используемая в формулах расчёта и привязках мнемосхем:
- `@/temperature` — переменная `temperature` на текущем объекте (`@`);
- `root.platform.devices.pump-01/temperature/value` — поле `value` переменной конкретного объекта;
- `@/fn/acknowledgeAlarm` — функция на текущем объекте;
- `@/evt/overheat` — событие на текущем объекте.

### `selectionKey` (Ключ выбранного объекта на экране)

Общее имя слота выбора на дашборде (например, `"device"`). Когда оператор кликает по строке в таблице устройств (`object-table`), у которой задан `selectionKey: "device"`, все графики, индикаторы и кнопки на этом же экране с таким же `selectionKey: "device"` автоматически переключаются на выбранное устройство. Подробнее: [Дашборды](dashboards.md).

## Принятые сокращения

| Сокращение | Расшифровка | Что означает |
|------------|-------------|--------------|
| **АСУ ТП / OT** | Автоматизированная система управления ТП / Operational Technology | Полевое оборудование, ПЛК, датчики и промышленные сети |
| **ПЛК (PLC)** | Программируемый логический контроллер | Промышленный контроллер, опрашиваемый драйвером ISPF |
| **HMI** | Human-Machine Interface | Человеко-машинный интерфейс (экраны и пульты оператора) |
| **SCADA** | Supervisory Control and Data Acquisition | Диспетчерский сбор данных, мнемосхемы, тренды и оперативное управление |
| **MES** | Manufacturing Execution System | Цеховой производственный учёт: заказы, партии, OEE, качество, генеалогия |
| **P&ID** | Piping and Instrumentation Diagram | Технологическая схема трубопроводов, ёмкостей, насосов и КИПиА |
| **OPC UA** | Open Platform Communications Unified Architecture | Промышленный стандарт обмена данными с ПЛК и серверами автоматизации |
| **MQTT** | Message Queuing Telemetry Transport | Лёгкий протокол передачи телеметрии через брокер сообщений («издатель — подписчик») |
| **SNMP** | Simple Network Management Protocol | Протокол мониторинга сетевого и серверного оборудования |
| **RBAC** | Role-Based Access Control | Ролевое разграничение прав доступа (`admin`, `operator` и пользовательские роли) |
| **OIDC / JWT** | OpenID Connect / JSON Web Token | Единый вход через внешний сервер авторизации (например, Keycloak) и токены API |
