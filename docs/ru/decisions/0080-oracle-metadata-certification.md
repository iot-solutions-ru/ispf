# ADR-0080: Сертификация метаданных на Oracle (дополнение к 0037)

## Статус

**Accepted** (2026-11-20) — политика и charter сертификации. **Amended 2026-11-22 — B1 pack + Lab green:** lab Flyway SQL авторизован, JDBC-драйвер остаётся на classpath оператора, Lab-green gate пройден на Oracle Database Free. **Prod: No — Lab green.** Oracle `ISPF_DB` стартует, только если в сборке есть Flyway pack и оператор добавил JDBC-драйвер Oracle, и только под B1 fences (`assertOracleB1Fences`). Oracle Database Free — не production-редакция; named-SKU Prod Yes не подписан.

Канонический текст: [EN ADR-0080](../../en/decisions/0080-oracle-metadata-certification.md).

## Контекст

`OracleDialect` и внешний Oracle через `DATA_SOURCE` не означают сертификацию `ISPF_DB`. Правила Oracle, которые формируют pack: `''` — это `NULL`; quoted identifier не может содержать двойную кавычку или NUL; схема — это пользователь БД; в 19c нет `BOOLEAN`, `SELECT` без `FROM` и row limit вместе с `FOR UPDATE`.

## Решение

- Scope — **B1 metadata** на именованной версии/редакции Oracle и JDBC driver (кандидаты: 19c или 23ai; в релизе 23.26 Oracle переименовал линию 23ai в «26ai»). Oracle Database Free — только lab.
- Journal/history вне B1; **нет** single-engine bypass в fences.
- **Lab green** достигнут (Amendment 3). Named-SKU Prod Yes — отдельный gate, открыт: Free ≠ Enterprise Edition.
- MySQL B1 Prod Yes подписан в [0079](0079-mysql-metadata-certification.md) (2026-11-22) — это разблокировало B1 pack Oracle.
- `assertEngineCertified` пропускает `oracle`, только если есть `classpath:db/migration/oracle/V1__baseline.sql` и загружается `oracle.jdbc.OracleDriver`; иначе отказ с инструкцией. `OracleJdbcDriverEnvironmentPostProcessor` отказывает ещё до создания DataSource. B1 fences — до Flyway и на context refresh: без row isolation, `HARD`, dual-write, cluster и JDBC history/journal на `ISPF_DB`; `PATCH` runtime-settings не включает JDBC journal на лету.
- ISPF не поставляет JDBC-драйвер Oracle и не заявляет права на его распространение.

### Amendment 1 — lab Flyway SQL

- `db/migration/oracle/V1__baseline.sql` генерируется `tools/oracle-baseline-generate.py` из postgresql `V1` + `V71`…`V101` (пропущены V86 RLS, V89 `random_uuid`). DDL по правилам 19c (Free 23.26 применяет): без `BOOLEAN`, без `IF NOT EXISTS`, одна строка на `INSERT`, `DEFAULT` перед `NOT NULL`.
- Типы: `VARCHAR(n)` → `VARCHAR2(n CHAR)` (`CLOB` свыше 4000), `TEXT` → `CLOB`, `BYTEA` → `BLOB`, `UUID` → `VARCHAR2(36 CHAR)`, `BOOLEAN` → `NUMBER(1)` + `CHECK (0, 1)`, `TIMESTAMP` → `TIMESTAMP(6)` с `LOCALTIMESTAMP`, identity → `GENERATED BY DEFAULT AS IDENTITY`.
- `''` хранится как `NULL`: три колонки `NOT NULL DEFAULT ''` (`platform_roles.description`, `federation_peers.path_prefix`, `platform_cluster_replicas.replica_capabilities`) здесь nullable; остальные `NOT NULL` текстовые колонки отвергают `''` (ORA-01400) — громкий отказ, а не тихая подмена.
- Зарезервированные слова `event_history.level`, `alarm_shelves.comment`, `alarm_shelf_requests.comment` — quoted lowercase; JPA-маппинг `comment` тоже в кавычках.
- `idx_object_nodes_path_prefix` пропущен (ORA-01408: столбец уже проиндексирован `UNIQUE`); retype `variable_samples.value_text` в `CLOB` — add / drop / rename на пустой таблице (ORA-22858).
- `UPDATE` / `DELETE` по таблицам без вставленных строк пропущены (95 операторов, no-op на пустой схеме); такой оператор по seeded-таблице, nullable unique-ключ, ключ шире ORA-01450 и непереведённый default валят генератор.
- Lockstep: `tools/oracle-flyway-lockstep-check.py` + `docs/en/oracle-flyway-exceptions.txt` в CI. Применённый V1 заморожен. DDL в Oracle авто-коммитится: при сбое V1 — пересоздать пользователя схемы и повторить.
- `flyway-database-oracle` (Apache-2.0, `runtimeOnly`, без драйвера); таблица истории Flyway на Oracle — lowercase `"flyway_schema_history"`.

### Amendment 2 — драйвер на classpath оператора

- `ojdbc*` **не** входит в дистрибутив: не `implementation` / `runtimeOnly`, нет в `bootJar`, portable zip и образе. Оператор сам берёт thin-драйвер (`ojdbc17` для JDK 17+) на условиях Oracle.
- Путь оператора: `java -Dloader.path=lib -cp ispf-server.jar org.springframework.boot.loader.launch.PropertiesLauncher` (launcher уже в JAR); шаги для JAR и контейнера — [checklist](../../en/oracle-sku-promotion-checklist.md#adding-the-oracle-jdbc-driver).
- Lab / CI: конфигурация Gradle `oracleLabJdbc` (`ojdbc17`, BOM `23.26.3.0.0`) — только с `-Dispf.test.oracleDocker=true` и задачей `copyOracleLabJdbc`; обычный CI её не скачивает, в SBOM её нет. Тесты: `testcontainers-oracle-free:2.0.5`.
- ojdbc отвергает `java.util.UUID` (ORA-17004): на Oracle основной DataSource оборачивается `OracleUuidJdbcDataSource` (UUID как текст `VARCHAR2(36)`). Hibernate: `OracleDialect` автоопределяется, `Instant` — как `TIMESTAMP` (ORA-18716).
- SQL диалекта: `FETCH FIRST ? ROWS ONLY`; голова аудит-цепочки — `ROWID` + `ROWNUM` (ORA-02014 в 19c); lock-row — `SELECT … FROM DUAL` (гонка → ORA-00001, игнорируется); claim задач — `FOR UPDATE SKIP LOCKED` без row limit, `PlatformJobService` читает одну строку.

### Amendment 3 — Lab-green gate

Flyway TCK (семантика `''`, quoted-колонки, `SKIP LOCKED` через `PlatformJobService`, concurrent audit 8 writers, lease failover — `OracleFlywayBaselineTckTest`), live boot + двойной import + alarm shelf через JPA (`OracleLiveBundleImportTckTest`), lab-стенд `tools/oracle-b1-lab` (health, login, Flyway, dialect, нет ojdbc в `bootJar`, отказ без драйвера, import + 4 пути, второй JVM, аудит) и boot refuse для row isolation, `HARD`, JDBC history, dual-write, JDBC journal, cluster плюс запрет hot-reload JDBC journal. Ячейка: Oracle AI Database 26ai Free 23.26.4.0.0, `AL32UTF8`, `MAX_STRING_SIZE=STANDARD`. Evidence: `tools/oracle-b1-lab/gate-evidence-lab-free.json` — 2026-11-22, 18 PASS / 0 FAIL. Docker TCK (`oracle-docker`) запускаются только opt-in (`-Dispf.test.oracleDocker=true`: нужен Docker, добавляется lab-драйвер), в обычном CI их нет; обычный CI гоняет unit-тесты boot refuse и lockstep.

Открыто до Prod Yes: named-редакция (Enterprise / SE2 19c или 23ai/26ai, или managed-сервис; tech debt **P-ORACLE-SKU**), прогон на 19c, Hibernate `ddl-auto=validate` (вне `local` — `SPRING_JPA_HIBERNATE_DDL_AUTO=none`), запись `''` в `NOT NULL` на не покрытых путях, PG-only SQL (bucket aggregate, `CLOB` через `=`), шифрование Oracle Net / TLS. `concatExpression` на Oracle — это `||`: NULL-операнд считается пустой строкой, а не даёт NULL, поэтому вызывающий код сам проверяет NULL (запрос триггеров SQL-binding так и делает).

## Последствия

Oracle — **Lab green, Prod: No**; смена движка — новая БД и импорт bundle. В продажах — «Oracle B1 metadata (lab, Oracle Database Free)», драйвер — от оператора, без заявлений об Enterprise Edition. MySQL B1 Prod Yes на Oracle не переносится; Prod Yes Oracle — только после своего named-SKU gate.
