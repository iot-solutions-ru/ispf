# Производственные шаблоны проектирования (MES и цеховой учёт)

> **Статус:** Charter — типовые архитектурные решения для задач производства, качества и прослеживаемости на базе пакетов `bundle.json` ([ADR-0050](decisions/0050-manufacturing-patterns-as-solutions.md)). Метки зрелости: [doc-status.md](doc-status.md).

В ISPF отраслевые механизмы производственного учёта (генеалогия партий, спецификации материалов, маршрутные карты, контроль качества и обмен с ERP) создаются **на уровне прикладного решения (`bundle.json`)** — с помощью изолированных SQL-таблиц, функций на узлах логики (`SINGLETON` / `INSTANCE`), процессов BPMN, дашбордов и отчётов, без утяжеления ядра платформы отраслевым Java-кодом.

**Связанные разделы:** [Каталог ISA-95](isa95-catalog.md) · [Соответствие ГОСТ Р МЭК 62264](gost-mek-62264-parts-2-3-4.md) · [Эталонное решение MES](reference-mes-platform.md) · [Руководство оператора ERP-MES](erp-mes-demo.md).

## 1. Каталог типовых производственных шаблонов

| Шаблон | Какую производственную задачу решает | Как собирается в ISPF |
|--------|--------------------------------------|-----------------------|
| **Граф прослеживаемости партий (`Traceability DAG`)** | Прямая и обратная генеалогия: из каких партий сырья, на каком оборудовании и по какому заказу выпущена готовая продукция | Таблицы узлов и рёбер партий в SQL-схеме приложения + функции обхода графа в BFF + экран генеалогии и печатный отчёт |
| **Многоуровневые спецификации (`Nested BoM`)** | Состав изделия по переделам, нормы расхода, допустимые замены материалов и расчёт потребности | Таблицы спецификаций и ревизий в схеме приложения + скриптовые функции расчёта списания |
| **Граф технологических операций (`Operations Graph`)** | Последовательность операций маршрутной карты, блокировки перехода, отправка на доработку (`rework`) | Таблицы операций + маршруты BPMN с задачами оператора в рабочей очереди (`Work Queue`) |
| **Конфигуратор заказных изделий (`CTO Configurator`)** | Проверка совместимости опций при приёме заказа и автоматическая генерация комплекта производственных заданий | Правила проверки параметров и функция формирования заказа на узле `SINGLETON` |
| **Пользовательские атрибуты без доработки кода** | Добавление специфичных для завода паспортов и характеристик к заказам, партиям и агрегатам | JSON-поля в таблицах приложения, переменные на шаблонах `INSTANCE` и примеси `MIXIN` |
| **Управление качеством и несоответствиями (`QMS Lite`)** | Входной и пооперационный контроль, акты о браке (`NCR`), изоляция партии и маршрут согласования решения технологом | Таблицы контрольных карт + процесс согласования в BPMN + отчёты по браку |
| **Надёжный обмен с 1С и SAP (`Integration Outbox / Inbox`)** | Гарантированная отправка подтверждений выпуска и приём плановых заказов без потери сообщений при обрывах связи | Таблицы `outbox` / `inbox` с ключом идемпотентности и доставкой через HTTP, NATS или Kafka ([Релей сообщений приложений](application-message-relay.md)) |
| **Технологические паспорта и этикетки (`Documents / Labels`)** | Печать маршрутных листов, бирок тары и сертификатов качества по данным партии | Узлы `REPORT` с прикреплёнными шаблонами XLSX / DOCX / HTML / PDF ([Отчёты](reports.md)) |
| **Внешний кабинет заказчика или аудитора (`Portal Role`)** | Безопасный доступ внешнего проверяющего или контрагента только к своим партиям и сертификатам | Выделенная роль и ветка тенанта (`ACL`) + отдельное приложение оператора только для чтения |

## 2. Архитектурное правило разделения ядра и прикладного решения

Все перечисленные производственные сущности принадлежат **пакету прикладного решения (`bundle.json`)**, который команда внедрения может свободно адаптировать под конкретный завод, версионировать в Git и обновлять независимо от релизов серверного ядра `ispf-server`.
