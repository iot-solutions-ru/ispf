# ADR-0079: MySQL metadata certification (amends 0037)

## Status

**Accepted** (2026-11-20) — policy and certification charter. **Amended 2026-11-22 — B1 pack + Lab green:** lab Flyway SQL is authorized (§ Amendment 1), the JDBC client driver is decided (§ Amendment 2), and the Lab-green gate (§ Amendment 3) passed on MySQL 8.4.13 Community. **Prod Yes (B1)** 2026-11-22 by owner extension (§ Amendment 4) on one cell: **MySQL Community Server 8.4.x + MariaDB Connector/J only** ([checklist](../mysql-sku-promotion-checklist.md)). **Amended 2026-11-23 — B2 single-engine:** opt-in `ISPF_MYSQL_SINGLE_ENGINE=true` puts JDBC history and journal on the same MySQL database (§ Amendment 5); **Prod Yes (B2)** 2026-11-23 by owner extension on the same cell ([B2 checklist](../mysql-b2-sku-promotion-checklist.md)). **Amended 2026-11-23 — A-A:** with the single-engine flag, `ispf.cluster.enabled=true` is allowed (§ Amendment 6); **Prod Yes (A-A)** by owner extension on the same cell ([A-A checklist](../mysql-aa-sku-promotion-checklist.md)); NATS still required; soak tech-debt **P-MYSQL-AA-SOAK**. A MySQL `ISPF_DB` boots only under its fences (`MetadataDialectBootPolicy.assertMysqlB1Fences`): B1 by default; B2/A-A with the flag (cluster only with the flag). Other MySQL cells are not Prod Yes (**P-MYSQL-SKU-RERUN**); MariaDB is never covered. TLS and SQL outside the gates' paths are not certified (**P-MYSQL-TLS**, **P-MYSQL-PG-SQL**).

Amends [0037-relational-core-portability](0037-relational-core-portability.md). MySQL 8.x is the next enterprise metadata target after MSSQL B1 lab-green / Prod Yes on the Evaluation cell in [0078](0078-mssql-metadata-certification.md). This ADR grants production support only for the § Amendment 4 cell.

## Context

ISPF has a `MysqlDialect` and, since the 2026-11-22 amendment, a generated greenfield MySQL Flyway pack. External MySQL through `DATA_SOURCE` is an integration path, not evidence that `ISPF_DB` can run on MySQL.

MySQL certification does **not** imply MariaDB certification. They have distinct SQL, JDBC, locking, and operational behavior and require separate evidence. Config `mariadb` and product-name MariaDB fail closed (not aliased to MySQL).

## Decision

- Scope the first gate to **B1 metadata** on a named MySQL version/edition. The lab cell is **MySQL 8.4 LTS Community**; 8.0 is not a signed cell.
- Keep journal and variable history outside the B1 claim. B2 (§ Amendment 5) covers them only under the opt-in single-engine flag; without it the fences still refuse JDBC history and journal.
- **Lab green** is reached (§ Amendment 3). **Prod Yes (B1)** covers one cell by owner extension (§ Amendment 4); every other MySQL cell needs its own checklist run.
- `MetadataDialectBootPolicy.assertEngineCertified` no longer hard-refuses `mysql`. Like MSSQL, a MySQL `ISPF_DB` boots only under its B1 fences, enforced pre-Flyway (`FlywayDialectConfiguration`) and on context refresh (`MysqlCertificationBootGuard`). Oracle has its own engine gate ([0080](0080-oracle-metadata-certification.md)).
- Require a greenfield Flyway pack, fixed bundle import, concurrent audit verification, lease/failover checks, and explicit unsupported-feature failures before promotion.
- Treat Testcontainers or a developer lab as lab evidence only, never as production certification. § Amendment 4 is an explicit owner exception for one cell.
- Do not reuse a MySQL result for MariaDB. A MariaDB claim requires its own charter, pack, named version, and gate.
- Do **not** add GPL `mysql-connector-j` to any classpath ([0016-agpl-dual-licensing](0016-agpl-dual-licensing.md)). The ISPF_DB client is the LGPL MariaDB Connector/J (§ Amendment 2).

### Amendment 1 (2026-11-22) — lab Flyway SQL authorized

- `db/migration/mysql/V1__baseline.sql` is the greenfield baseline, generated by `tools/mysql-baseline-generate.py` from postgresql `V1` + `V71`…`V101`. Skipped: `V86` (PG RLS), `V89` (`random_uuid`), and `regexp_replace` data rewrites (no-ops on an empty database).
- Type map: `UUID` → `CHAR(36)`, `BOOLEAN` (stored `TINYINT(1)`), `TIMESTAMP` → `DATETIME(6)` with `CURRENT_TIMESTAMP(6)` defaults, `TEXT` → `LONGTEXT`, `BYTEA` → `LONGBLOB`, identity → `AUTO_INCREMENT`. Every table is InnoDB, `utf8mb4`, `utf8mb4_0900_bin` (case-sensitive, NO PAD — PostgreSQL equality for object paths).
- MySQL 8.4 parses and ignores inline `REFERENCES`; the generator emits table-level `FOREIGN KEY` constraints (11, `ON DELETE CASCADE` kept). Two non-unique indexes exceed the 3072-byte InnoDB key limit and get computed prefixes (`variable_samples.object_path(510)`, `historian_catchup_ranges.series_key(766)`). A unique key over the limit fails the generator: a prefix would change uniqueness.
- Lockstep: `tools/mysql-flyway-lockstep-check.py` + `docs/en/mysql-flyway-exceptions.txt` run in CI. An applied `mysql/V1` is frozen; a new PG `Vnn` needs a `mysql/Vnn` twin or an exception line, not a regenerated V1.
- MySQL DDL is not transactional. A failed V1 leaves a partial schema: drop the database and retry.

### Amendment 2 (2026-11-22) — driver decision (client ≠ server)

| Item | Decision |
|------|----------|
| ISPF_DB JDBC client for MySQL 8.4 servers | MariaDB Connector/J `org.mariadb.jdbc:mariadb-java-client` (LGPL-2.1-or-later), `runtimeOnly`, shipped unmodified as its own JAR |
| URL / driver | `jdbc:mysql://host:3306/ispf?permitMysqlScheme=true` with `spring.datasource.driver-class-name=org.mariadb.jdbc.Driver` (Connector/J 3.x refuses `jdbc:mysql:` without `permitMysqlScheme`) |
| Flyway | `org.flywaydb:flyway-mysql`, `runtimeOnly` |
| Tests | `org.testcontainers:testcontainers-mysql:2.0.5`, `testImplementation` |
| GPL `mysql-connector-j` | Not on any classpath |
| MariaDB **server** | Still refused. Config `mariadb`, product-name MariaDB, and an explicit `ISPF_METADATA_DB_KIND=mysql` against a MariaDB server all fail closed (`RelationalDialectDetector`). A MariaDB-made client does not make the server MariaDB, and a MySQL result says nothing about a MariaDB server |
| Hibernate | A `MySQLDialect` is pinned on a MySQL `ISPF_DB` (`RelationalConfiguration`). Hibernate maps any driver named "MariaDB…" to `MariaDBDialect`, even against a MySQL server. The pin is `MysqlHibernateDialect`, which also makes `ddl-auto=validate` pass (§ Amendment 3) |
| Audit / script locks | `MysqlDialect.ensureLockRow` uses `INSERT … ON DUPLICATE KEY UPDATE`: the portable `INSERT … WHERE NOT EXISTS` deadlocked (1213) under 8 concurrent first-time lockers |

### Amendment 3 (2026-11-22) — Lab-green gate

Lab green means every item below passed on one named lab cell. It is **not** Prod Yes.

| # | Gate | Evidence |
|---|------|----------|
| 1 | Empty MySQL 8.4 → Flyway `mysql/V1`; tables on `utf8mb4_0900_bin`; case-sensitive paths; role seed; `SKIP LOCKED` job SQL; job queue round trip and function-success SQL-binding triggers (since the P-MYSQL-PG-SQL fix) | `MysqlFlywayBaselineTckTest` (`mysql-docker`) |
| 2 | Concurrent audit-chain append (8 writers) + hash verify; driver lease failover between two owners | `MysqlFlywayBaselineTckTest` |
| 3 | Spring Boot boot on MySQL with a pinned Hibernate `MySQLDialect` + cert-bundle import + `by-path` (since the validate fix: `MysqlHibernateDialect` with `ddl-auto=validate`) | `MysqlLiveBundleImportTckTest` (`mysql-docker`) |
| 4 | Lab stand: engine cell, health, login, Flyway V1, dialect, cert import + 4 paths, second JVM, serial re-import + audit chain | [`tools/mysql-b1-lab`](../../../tools/mysql-b1-lab/README.md) |
| 5 | Boot refusals: row isolation, `HARD`, JDBC history, dual-write, JDBC journal, cluster, MariaDB server (explicit kind and auto-detect) | Lab stand + `MysqlCertificationBootGuardTest`, `FlywayDialectConfigurationMysqlTest`, `RelationalDialectDetectorTest` |

Lab cell: MySQL **8.4.13 Community** (`mysql:8.4`), `transaction_isolation=READ-COMMITTED`, database `ispf` on `utf8mb4_0900_bin`, single JVM, `local` profile (`ddl-auto=none`, same as the MSSQL B1 stand). Signed run: [`gate-evidence-lab-community.json`](../../../tools/mysql-b1-lab/gate-evidence-lab-community.json) — 2026-11-22, 17 PASS / 0 FAIL. Checklist: [mysql-sku-promotion-checklist](../mysql-sku-promotion-checklist.md).

Closed after Lab green (2026-11-22): Hibernate `ddl-auto=validate` (default profile). MariaDB Connector/J reports neither lower-, upper- nor mixed-case identifier storage for a MySQL server with `lower_case_table_names=0`, so Hibernate looked tables up in upper case and reported them missing; with names resolved, `report_templates.content` (`BINARY` mapping, `LONGBLOB` column) failed the type check. `RelationalConfiguration` now pins `MysqlHibernateDialect`, which keeps names as written when the driver reports no case (a reported case still wins) and accepts `LONGBLOB` for `BINARY` mappings. `MysqlLiveBundleImportTckTest` boots with validate on MySQL 8.4.13 with `lower_case_table_names=0`. No operator property is needed; an explicit `hibernate.dialect` replaces the pin and brings the failure back.

### Amendment 4 (2026-11-22) — Prod Yes (B1) by owner extension

| Item | Decision |
|------|----------|
| Cell | **MySQL Community Server 8.4.x** LTS, self-managed, with **MariaDB Connector/J** as the only `ISPF_DB` client |
| Basis | The § Amendment 3 Lab-green cell (8.4.13 Community, local Docker), re-run 2026-11-22 with `ddl-auto=validate` on the stand JVM and the second JVM, plus platform metrics and the job queue: 20 PASS / 0 FAIL ([`gate-evidence-validate-community.json`](../../../tools/mysql-b1-lab/gate-evidence-validate-community.json), collector output). Owner decision: [`gate-evidence-prod-yes-community.json`](../../../tools/mysql-b1-lab/gate-evidence-prod-yes-community.json) |
| Owner extension | The lab Docker cell stands in for a named self-managed host, overriding the checklist's "not the lab Docker stand" rule for this cell only. A gate re-run on the first named host is recommended, not blocking |
| Fences | Unchanged: boot refuses JDBC history / journal, dual-write, cluster, row isolation, `HARD`, and MariaDB servers |
| TLS | Operator-required; **not certified** by this signature. The evidence cell ran without TLS, with `allowPublicKeyRetrieval=true`, which is lab-only. Tech debt **P-MYSQL-TLS** ([checklist](../mysql-sku-promotion-checklist.md#known-gaps-tracked-tech-debt)) |
| SQL coverage | The paths the gate and the MySQL TCKs exercise; **no** full SQL parity with PostgreSQL. The PostgreSQL-only SQL found at signing is fixed through `RelationalDialect` and runs on MySQL 8.4: `PlatformJobService` reads `job_id` as a string instead of casting `getObject` on `CHAR(36)` to `UUID`, and orders running jobs with `orderByNullsLast` instead of `NULLS LAST` (queued report runs, `GET /api/v1/platform/metrics`); `ApplicationSqlBindingStore` builds function-success trigger lists with `concatExpression` (`CONCAT`) instead of `\|\|`, which MySQL reads as OR. The remaining SQL is not reviewed in full. Tech debt **P-MYSQL-PG-SQL** ([checklist](../mysql-sku-promotion-checklist.md#known-gaps-tracked-tech-debt)) |
| Tech debt | **P-MYSQL-SKU-RERUN** — MySQL Enterprise, HeatWave, Amazon RDS / Aurora MySQL, Azure Database for MySQL, and every other non-Community cell need their own checklist run before a claim names them |
| Non-claims | MySQL 8.0 and 9.x; MariaDB Server; any other JDBC client (GPL `mysql-connector-j` is never on the classpath); B2 history / journal (signed later, § Amendment 5); active-active; tenant row isolation; `HARD` and per-app schemas; TLS on the `ISPF_DB` connection (**P-MYSQL-TLS**); full SQL parity with PostgreSQL (**P-MYSQL-PG-SQL**) |

### Amendment 5 (2026-11-23) — B2 single-engine (opt-in) and Prod Yes (B2) by owner extension

B2 follows MSSQL B2 ([0078](0078-mssql-metadata-certification.md) § 1): B1 plus `ISPF_VARIABLE_HISTORY_STORE=jdbc` and `ISPF_EVENT_JOURNAL_STORE=jdbc` on the **same** MySQL database, so configuration, historian and journal live in one database. It is opt-in; B1 stays the default.

| Item | Decision |
|------|----------|
| Switch | `ISPF_MYSQL_SINGLE_ENGINE=true` (`ispf.relational.mysql.single-engine`, default `false`). Set it explicitly: deploy profile `mysql-single-engine` fills only keys no property source defines, and `application.yml` defines this one ([B2 checklist](../mysql-b2-sku-promotion-checklist.md#deploy-profile)) |
| Store rules (pre-Flyway and on context refresh) | With the flag, the history store must be exactly `jdbc` (ClickHouse, Cassandra/Scylla, `jpa` and typos refused) and an enabled journal must be JDBC; warm tier, cold Parquet archive and the ClickHouse spool are refused. The rules are the MSSQL single-engine rules, in one shared check |
| Still refused with the flag (before § Amendment 6) | Dual-write, row isolation, `HARD`, MariaDB servers. Cluster was refused until § Amendment 6. The flag on any engine other than MySQL is refused, because it clamps retention wherever it is set |
| Preflight | With the flag, boot refuses unless the pool's session runs `READ-COMMITTED` and the database default collation is `utf8mb4_0900_bin` (`MysqlDatabasePreflightRunner`) |
| Bucket aggregate | Native `MysqlDialect.variableSampleBucketAggregateSql`: `TIMESTAMPDIFF` / `TIMESTAMPADD` on the `DATETIME(6)` `observed_at` (UTC wall clock as written), epoch-aligned like PostgreSQL and the JVM path, and independent of the session `time_zone` and the JVM zone. `/history/aggregate` runs it in SQL; MySQL no longer falls back to aggregating rows in the JVM |
| Journal purge | `DELETE … LIMIT 5000`, one transaction per batch; the loop is shared with MSSQL `DELETE TOP (5000)` |
| Retention | Application `DELETE`. Every variable's retention is clamped to `ispf.relational.mysql.max-retention-days` (default **90**), and ≤0 (unlimited) becomes that ceiling. No rollups, partitions or partition drop on MySQL |
| Schema | No migration: `mysql/V1` already carries `variable_samples` and `event_history` |
| Gate | [`gate-evidence-b2-community.json`](../../../tools/mysql-b1-lab/gate-evidence-b2-community.json): 25 PASS / 0 FAIL on MySQL 8.4.13 Community, 2026-11-23 — live historian write, native bucket aggregate, raw read, retention ceiling, live journal and keyset read, 20,000-row purge, 6 boot refusals, 2 preflight refusals. CI (opt-in Docker): `MysqlHistoryBucketTckTest` |
| Prod Yes (B2) | Owner extension 2026-11-23 on the § Amendment 4 cell only, with the flag on, a dedicated database and a dedicated server instance (no co-tenant OLTP). Owner decision: [`gate-evidence-b2-prod-yes-community.json`](../../../tools/mysql-b1-lab/gate-evidence-b2-prod-yes-community.json) |
| Non-claims (B2 alone) | Rollups, partitions and partition-drop retention; a file buffer in front of MySQL; a multi-year raw archive; raw-scan latency without a named fixture; non-Community cells (**P-MYSQL-SKU-RERUN**); MariaDB; TLS (**P-MYSQL-TLS**); full SQL parity (**P-MYSQL-PG-SQL**). Active-active is § Amendment 6 |

### Amendment 6 (2026-11-23) — A-A (active-active) on the single-engine cell

A-A follows MSSQL A-A ([0078](0078-mssql-metadata-certification.md)): **N JVMs, one writable primary**, not multi-master. Cluster is allowed only together with `ISPF_MYSQL_SINGLE_ENGINE=true` (the dual-JVM gate ran with history and journal on this database).

| Item | Decision |
|------|----------|
| Switch | `ISPF_CLUSTER_ENABLED=true` **and** `ISPF_MYSQL_SINGLE_ENGINE=true`. B1 with cluster still refuses boot |
| Dependencies | `ClusterDependencyValidator` still requires NATS JetStream (and Redis when live-variable sync / path interest is on). No “no-NATS” claim |
| Topology | One writable MySQL primary; every replica uses the same `ISPF_METADATA_DB_KIND` and `ISPF_DB_URL` |
| Gate | [`tools/mysql-b1-lab/gate-aa.ps1`](../../../tools/mysql-b1-lab/gate-aa.ps1) + [`stand-aa-local.ps1`](../../../tools/mysql-b1-lab/stand-aa-local.ps1); CI opt-in `MysqlClusterLeaseTckTest` |
| Prod Yes (A-A) | Owner extension on the § Amendment 4 / 5 Community cell; evidence [`gate-evidence-aa-prod-yes-community.json`](../../../tools/mysql-b1-lab/gate-evidence-aa-prod-yes-community.json) (measurements [`gate-evidence-aa-community.json`](../../../tools/mysql-b1-lab/gate-evidence-aa-community.json), 35/0). Residual dual-JVM chaos soak / failover under load is tech-debt **P-MYSQL-AA-SOAK** ([checklist](../mysql-aa-sku-promotion-checklist.md)) |
| Non-claims | Multi-master Group Replication; readable secondaries as write targets; cluster without NATS; completed multi-hour soak (**P-MYSQL-AA-SOAK**); non-Community cells |

## Consequences

- MySQL is **Prod Yes (B1)** on one cell: self-managed MySQL Community Server 8.4.x with MariaDB Connector/J, under the B1 fences. On the same cell, opt-in single-engine is **Prod Yes (B2)**: JDBC history and journal in the same database, retention `DELETE` capped at 90 days by default. With the same flag, **Prod Yes (A-A)** allows `ispf.cluster.enabled` (NATS still required; soak **P-MYSQL-AA-SOAK**). Other MySQL cells stay lab-only until their own checklist runs (**P-MYSQL-SKU-RERUN**). TLS is operator-required and not certified (**P-MYSQL-TLS**); SQL outside the gates' paths is not claimed (**P-MYSQL-PG-SQL**).
- Sales and documentation must name **MySQL Community Server 8.4 B1 metadata**, **B2 single-engine**, and **A-A** where they apply, with the MariaDB Connector/J client, and must not say “MySQL/MariaDB” or name Enterprise / managed MySQL without a re-run.
- Engine changes remain greenfield database plus bundle import, not in-place migration.
- MySQL B1 Prod Yes (§ Amendment 4) unblocked the Oracle B1 pack ([0080](0080-oracle-metadata-certification.md)). Oracle Free has its own Prod Yes (B1); Oracle B2/A-A are separate trains.
